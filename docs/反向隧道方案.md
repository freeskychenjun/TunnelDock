# 反向隧道方案（wss 传输层，代号 RT）

> 背景：本地 ISP 对 cloudflared 边缘 7844 端口做 DPI 封锁（QUIC/http2 同掐），
> TunnelDock 现有 cloudflared 传输层在同一出口网络下不可用。本方案把已实测验证的
> cf-worker-tunnel（Worker + Durable Object + wss 443 反连 agent）移植进 TunnelDock，
> 作为第二种传输模式，供被封网络的同事长期使用。

## 0. 结论速览

- **传输层替换**：`cloudflared 反连 7844` → `本机 agent wss 直连 443`
- **部署归属**：每位用户自己的 Cloudflare 账号 + 域名（免费 Worker 计划够用）
- **首次部署**：应用内向导全自动（填 API Token → 自动建 DNS/部署 Worker/写配置）
- **架构不变的部分**：服务卡片 UI、PIN 网关理念（登录页/限速/token 引导）、
  断线重连状态机、托盘常驻、开机自启

## 1. 目标架构

```
手机(任意网络) → CF 边缘 443 → Worker(路由+鉴权) → DO(每服务一个实例)
                                        ↑ hibernation WS
桌面应用 TunnelDock ── agent 模块 ── wss://<域名>/__agent?secret=... （443，不碰 7844）
                          ↓
                    127.0.0.1:目标端口（HTTP/SSE/WS 全通道）
```

- 一个 Cloudflare 账号 = 一个 Worker（一个 script）+ 一组 DO 实例
- 每个发布（ServiceConfig）= 一个子域名 + 一个 DO 实例（idFromName(serviceId)）+ 一条 agent wss 连接
- PIN 鉴权在 DO 侧做（cookie + ?k= 兜底 + IP 限速），**不再需要本地 proxy.cjs 网关**
  （网关的"剥 Origin/重写 Host/token 引导"职责移入 agent 的转发层）

## 2. 模块与文件规划

| 模块 | 位置 | 职责 |
|---|---|---|
| Worker/DO | `src/worker/tunnel.js`（新） | 从 cf-worker-tunnel/index.js 泛化：PINS 从 KV/DO storage 读（不再 wrangler.toml 硬编码）、按 serviceId 路由 DO、保留登录页/?k=/限速/WS 中转全套 |
| agent（Node 版） | `src/agent/agent.js`（新） | 移植 agent.py：node:http 直连目标、req/chunk/end 帧转发、ws-open/data/close 中转、剥 Origin/Host 归一、token 引导、指数退避。经 rollup 打包成 `out/main/agent.js`（同 gateway 模式，asarUnpack） |
| CF API 客户端 | `src/main/cloudapi.ts`（新） | 纯 fetch 调 CF API v4：Token 校验、zone 查找、DNS 记录增删、Worker script 上传（multipart，含 DO binding metadata）、路由/自定义域绑定 |
| 部署向导（UI） | `App.vue` + `ipc.ts` | 首次使用引导：Token 粘贴 → 选 zone/填子域 → 进度（建 DNS → 传 Worker → 验证）→ 落盘账号配置 |

| 边缘 IP 探测 | `src/agent/edgepin.ts`（新） | 替代 hosts 钉 IP：进程内探测候选 CF 边缘 IP 列表，wss/https 连接用 `host: ip + servername: 域名` 直拨（无需改 hosts、无需管理员） |

## 3. Worker 侧改动（相对 cf-worker-tunnel/index.js）

1. **PINS 动态化**：`parsePins(env)` 改为 `env.PINS_JSON`（部署时由应用写入全部
   服务映射）+ DO storage 覆盖层（改 PIN 不重部署 Worker，仅 PUT storage）。
2. **serviceId 路由**：`host.split(".")[0]` 改为 hostname→serviceId 映射（同在
   PINS_JSON），DO idFromName(serviceId)——子域名与 service 名解耦，重命名不发 DNS 变更。
3. **AGENT_SECRET**：每安装实例一个随机 secret（首次部署时生成，存 services.json
   同级 `account.json`；Worker env 与本地各一份）。
4. **DO 钉旧代码坑（B1）**：agent 重连即新 DO 唤醒，天然规避；改 PIN 走 storage 不
   重部署也规避。部署 Worker 后应用自动提示"所有服务将自动重连"。
5. 多 agent 互踢：DO 仍"最新连接赢"，但 serviceId 隔离后每服务独立 DO，互不影响。

## 4. transport 选择

- `ServiceConfig.transport?: 'cloudflared' | 'wss'`（缺省自动探测：启动时先试
  cloudflared 命名隧道 3 次，全败则提示切换 wss 模式；也可在设置里全局强制）
- wss 模式下 `hostname` 必填（子域名由应用按 `<serviceId>.<zone>` 生成）；
  Quick Tunnel（随机域名）在 wss 模式不可用——Worker 方案必须自有域名

## 5. agent（Node 版）技术要点

- 依赖 `ws`（仅 agent 打包产物内，主进程不引）；rollup 打包成单文件 `out/main/agent.js`
- HTTP 转发用 `node:http` 手写请求头组装（抄 agent.py：剥 host/connection/
  transfer-encoding/upgrade/content-length/accept-encoding/origin，补
  Content-Length + Connection: close）
- 响应体三种模式（chunked/content-length/EOF）流式转 chunk 帧，32KB 分片
- WS 中转：connId → 本地 ws 客户端 + 未连上先缓冲；Cookie 透传、Origin 不转发
- token 引导：与 proxy.cjs/agent.py 同策略（401 + 无 token 参数 → 读 tokenFile 303）
- 与主进程通信用 stdout JSON 行（状态/日志），同 gateway 模式

## 6. 部署向导流程（应用内全自动）

1. 用户在 CF 控制台建 "Edit zone DNS + Workers Scripts edit" 权限 Token（向导给直链）
2. 粘贴 Token → `GET /user/tokens/verify` 校验 → 列 zones 让用户选
3. 生成 AGENT_SECRET（crypto.randomBytes(32).hex）
4. `POST /zones/:id/dns_records`（A 记录 192.0.2.1 proxied:true，每服务一条）
5. `PUT /accounts/:id/workers/scripts/tunneldock-rt`（multipart：module 代码 +
   metadata 含 DO binding + routes + vars.PINS_JSON/AGENT_SECRET）
6. 验证：agent 连上 + `GET https://<sub>.zone/` 返回登录页
7. 账号配置落 `%APPDATA%\TunnelDock\data\account.json`（Token 用 DPAPI 加密存）

## 7. 复用与红线

- Worker/DO 代码基于自研 cf-worker-tunnel（无 GPL 问题）
- 不复制 dsh-pocket 代码；agent.py 为自研可自由移植
- 仓库 public：AGENT_SECRET/Token/PIN 永不进 git；account.json 加入 .gitignore 模式说明
- `src/gateway/proxy.cjs` 保持不动（cloudflared 模式继续可用）
- e2e：新增 `scripts/e2e-rt.ps1`（wss 模式全链路：登录/取页/WS/错误 PIN 限速/断线重连）

## 8. 里程碑

- M1：Worker `src/worker/tunnel.js` 泛化 + cloudapi.ts（Token 校验/zone/DNS/部署）
- M2：agent.js（Node 版）+ rollup 双入口 → 单服务手动配置打通 HTTP+SSE+WS
- M3：ipc.ts runtime 集成 + 部署向导 UI + transport 自动探测
- M4：e2e-rt、打包 dist、写同事版安装手册
