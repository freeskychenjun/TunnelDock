# TunnelDock 开发方案

> 产品定位：一个 Windows 桌面应用，把内网的 Web 服务（HTTP/WebSocket）**一键、安全、免费**地发布到公网访问。
> 技术栈：Electron。本方案基于 2026-09 手工搭建同类系统（auth-proxy + cloudflared + 计划任务）与
> 通读 dsh-pocket 2.10.6 源码的实战经验编写，所有坑均有实测依据。
>
> 版本：v0.1（初稿）　日期：2026-09-17　状态：待评审

---

## 1. 项目概述

### 1.1 要解决的问题

内网服务（家里 NAS 的管理页、本机开发的 Web 应用、公司内网测试环境……）想从外面访问，
传统手段要么需要公网 IP / 路由器端口映射 / DDNS，要么用 VPN 组网，对普通用户门槛高。

Cloudflare Tunnel（cloudflared）已经免费解决了「打洞」问题，但它是命令行工具，且：

- Quick Tunnel 地址每次启动随机变化，没有 UI 告知用户；
- 隧道本身**零鉴权**——服务直接裸奔公网；
- 无开机自启、断线重连、多服务管理；
- 在国内网络环境下二进制下载经常失败。

TunnelDock = cloudflared 的产品化外壳 + 访问控制层 + 生命周期管理，让这件事变成
「选端口 → 点发布 → 扫码」三步。

### 1.2 目标与非目标

**目标（v1.0）**

- Windows 10/11 桌面应用（托盘常驻），无需公网 IP、无需路由器配置；
- 多服务管理：每个"发布"= 名称 + 本地端口，独立启停、独立 PIN；
- 默认安全：每个发布自带 PIN 口令墙 + 限速防爆破 + WebSocket 透传；
- 两种隧道模式：免费 Quick Tunnel（地址随机）与命名隧道（用户自己的 Cloudflare 账号 + 域名，地址固定）；
- 开机自启、崩溃自恢复、cloudflared 断线重连；
- 手机友好：发布成功即出二维码/短链提示。

**非目标（v1.x 不做）**

- **跨平台**：只支持 Windows 10/11（已定）。不做 macOS/Linux 适配，也不为跨平台预留抽象——
  自启用 `setLoginItemSettings`+计划任务、进程树管理走 `taskkill /T` 语义、打包只出 NSIS，
  全部按 Windows 原生方式实现；
- TCP/UDP 非 HTTP 协议转发（cloudflared 支持，但 v1 聚焦 HTTP/WS）；
- 自建隧道服务端（不做 frp/ngrok 替代品，始终基于 Cloudflare 免费基础设施）；
- 团队协作/账号体系。

### 1.3 差异化定位

| 竞品 | 弱点 | TunnelDock 对应优势 |
|---|---|---|
| cloudflared CLI | 无 UI、无鉴权、地址漂移无感知 | 全部产品化 |
| ngrok / cpolar | 免费额度限制多、需注册、国内慢 | Cloudflare 免费额度大、无需注册即可用 Quick Tunnel |
| frp | 需要有公网服务器 | 零服务器 |
| Tailscale Funnel | 需全设备组网 | 浏览器直接访问 |

**核心卖点：免费 + 无注册（Quick 模式）+ 中文体验 + 默认安全 + 多服务面板。**

## 2. 需求与功能清单

### 2.1 用户故事

1. 我在 localhost:5173 跑了个演示应用，想让客户在手机上看 —— 选端口、点发布、发二维码，30 秒内完成。
2. 我家的 Home Assistant（192.168.1.10:8123）想在外面长期访问 —— 配置一次，开机自启，固定域名，PIN 保护。
3. 我临时给同事看个内网管理系统 —— 用完点停止，立即断开公网入口。

### 2.2 功能分级

**P0（MVP，没有就不成立）**

- F1 服务发布：名称 + 目标地址（host:port），启/停，状态显示（启动中/在线/离线）
- F2 自动获取 cloudflared：随安装包内置 + 支持手动放置 + 多镜像下载
- F3 PIN 口令墙代理：网页登录页 + HttpOnly Cookie + Basic Auth + 限速 + 常量时间比较 + WS 透传
- F4 发布结果展示：公网 URL、二维码、一键复制、PIN 展示/重置
- F5 单实例 + 托盘常驻 + 关闭到托盘

**P1（产品化）**

- F6 多服务列表持久化（electron-store / JSON）
- F7 开机自启（app.setLoginItemSettings + 计划任务兜底）+ 崩溃自动重启
- F8 cloudflared 断线检测与自动重连、URL 变更后自动刷新 UI
- F9 命名隧道模式：Cloudflare 账号登录（cert.pem）、创建/选择隧道、绑定域名
- F10 每服务独立 PIN + PIN 自定义 + 「记住我」会话时长配置

**P2（增值）**

- F11 访问日志与简单统计（IP、时间、路径、拦截记录）
- F12 IP 黑白名单、Cloudflare Access 联动提示
- F13 局域网直连模式（同网时绕过隧道，提示 `http://IP:端口`）
- F14 自动更新（考虑国内网络，首选检查+手动下载模式）

## 3. 架构设计

### 3.1 总体架构

```
┌────────────────────────────────────────────────┐
│ Electron                                        │
│  ┌──────────┐   IPC(contextBridge)  ┌────────┐ │
│  │ Renderer │◄─────────────────────►│  Main  │ │
│  │ Vue3+Vite│                       │ 进程    │ │
│  │ 服务面板  │                       │        │ │
│  └──────────┘                       └───┬────┘ │
└─────────────────────────────────────────┼──────┘
                                          │ 管理/spawn
                    ┌─────────────────────┼──────────────────┐
                    ▼                     ▼                  ▼
          ┌──────────────────┐  ┌────────────────┐  ┌──────────────┐
          │ gateway-proxy    │  │ cloudflared.exe│  │ service-     │
          │ (utilityProcess) │  │ (每发布一个)    │  │ registry     │
          │ PIN墙+限速+透传   │  │ Quick/命名隧道  │  │ (JSON 持久化) │
          └────────┬─────────┘  └────────────────┘  └──────────────┘
                   │ 127.0.0.1:31xxx
                   ▼
          ┌──────────────────┐
          │  本地目标服务      │
          │  (如 :5173)      │
          └──────────────────┘

  手机浏览器 ──https──► Cloudflare 边缘 ──隧道──► cloudflared ──► gateway-proxy ──► 本地服务
```

### 3.2 进程模型与模块划分

| 模块 | 进程 | 职责 | 关键点 |
|---|---|---|---|
| `main/` | Main | 应用生命周期、托盘、窗口、IPC 路由、模块编排 | 单实例锁 `requestSingleInstanceLock` |
| `main/tunnel-manager.ts` | Main | cloudflared 二进制定位/下载、spawn、stdout 解析出 trycloudflare URL、断线监听 | 二进制解析顺序：内置目录 → PATH → 用户手动放置 → 镜像下载 |
| `main/gateway.ts` | Main | 每个发布起一个 `utilityProcess` 跑反向代理 | 用 utilityProcess 隔离，代理崩溃不拖垮主进程 |
| `gateway/proxy.mjs` | Utility | PIN 墙反代：登录页、Cookie、Basic、限速、WS upgrade 透传 | 零第三方依赖，纯 node:http + node:net |
| `main/registry.ts` | Main | 服务配置 CRUD + JSON 持久化（原子写） | 写临时文件再 rename，防半截 JSON |
| `main/autostart.ts` | Main | 开机自启 | `setLoginItemSettings` 优先，计划任务兜底（注意电池标志坑） |
| `main/named-tunnel.ts` | Main | Cloudflare 登录（cert.pem）、隧道 CRUD、DNS 路由 | `cloudflared tunnel login/create/route/dns` 命令包装 |
| `renderer/` | Renderer | Vue3 面板：服务列表、发布向导、二维码、设置 | 全部经 preload 暴露的类型化 API，禁 nodeIntegration |

### 3.3 一次"发布"的时序

1. 用户填名称 + `127.0.0.1:5173`，点发布；
2. main 分配本地代理端口（如 31001），spawn utilityProcess 跑 gateway-proxy → 探活；
3. spawn cloudflared：`cloudflared tunnel --url http://127.0.0.1:31001 --no-autoupdate`；
4. 从 cloudflared stderr 解析 `https://xxx.trycloudflare.com`（带 60s 超时与重试）；
5. 状态机：`starting → ready(url) `；写 registry，通知 renderer 显示 URL + 二维码；
6. 手机扫码 → PIN → HttpOnly Cookie（12h）→ 之后免密访问；
7. 用户点停止：kill cloudflared（进程树）→ 停代理 → 状态 `stopped`，公网地址立即失效。

### 3.4 安全设计（默认基线，不可关闭）

- **PIN 墙默认开启**：8 位数字或自定义口令；登录失败限速（如同 IP 5 次/分钟，指数退避）；
  常量时间比较（`crypto.timingSafeEqual`）；
- Cookie：HttpOnly + SameSite=Strict + 12h 过期，不设 Domain；
- 代理不信任 `x-forwarded-for`（可伪造），用 socket remoteAddress 记日志；
- UI 明示风险：发布页固定文案「该地址公网任何人可见，仅由 PIN 保护」；
- 命名隧道模式下在文档中引导用户叠加 Cloudflare Access；
- cloudflared 加 `--no-autoupdate`（Windows 上它本来也不自更，显式声明）；
- 本地代理只监听 127.0.0.1（cloudflared 在同机回连），**不暴露局域网**，避免绕过 PIN 直连。

## 4. 关键技术方案（实测经验）

### 4.1 cloudflared 二进制管理

- **内置**：安装包打包 cloudflared-windows-amd64.exe（约 52MB，注意安装包体积；可在首次启动时引导下载替代）；
- 解析顺序（借鉴 dsh-pocket 且修正其缺陷）：`设置中用户指定路径 → 应用 resources 内置 → PATH → 下载`；
- 下载源队列：GitHub 官方 → ghproxy.net / gh.ddlc.top / gh-proxy.com 镜像（实测国内四个都可能全挂，
  所以"手动放置"是必须的一等公民入口，不是兜底）；
- 版本钉死并记录，升级随应用版本走。

### 4.2 PIN 反代（gateway-proxy）

以本会话实测通过的 auth-proxy.js 为蓝本通用化：

- 保留：登录表单页（适配手机 viewport）、HttpOnly 会话 Cookie、Basic Auth（供 curl）、
  WS upgrade 透传（握手带 Cookie 校验）、常量时间比较；
- 新增：按 IP 限速（令牌桶）、每服务独立 PIN、访问日志钩子；
- 去掉：DSH 特有的 launch token 注入与 Host/Origin 归一（那是 DSH 的围栏，通用服务无此问题；
  但保留可选的 Host 重写开关，应对个别校验 Host 的本地服务）；
- 响应注入：可选地在登录页显示服务名称，帮助用户确认扫对了码。

### 4.3 地址漂移的应对（Quick 模式核心体验）

- 发布成功即弹二维码 + 复制按钮；
- cloudflared 进程退出重连后 URL 必变 → 状态机监听 `onExit`，自动重启并刷新 UI 中的 URL，
  同时发系统通知「地址已更新，请重新扫码」；
- 长期使用场景引导用户切换命名隧道模式（固定域名）。

### 4.4 命名隧道模式（P1）

- `cloudflared tunnel login` → 浏览器授权 → cert.pem；
- `cloudflared tunnel create <name>` + `tunnel route dns <name> <sub.domain.com>`；
- 运行用 credential JSON + config 文件（`--config` 指定 ingress 规则）；
- 前提提示：用户需持有 Cloudflare 账号与一个域名（免费计划即可）。

### 4.5 生命周期与 Windows 实测坑

| 坑 | 对策 |
|---|---|
| 开机自启失效（笔记本电池） | `setLoginItemSettings` 之外，计划任务方案要显式关 `DisallowStartIfOnBatteries` |
| 常驻子进程被父会话连带杀死 | cloudflared 由 Electron main（常驻进程）直接持有，Electron 退出前显式 kill 进程树 |
| PowerShell 脚本中文乱码 | 所有 .ps1 一律 UTF-8 with BOM（本项目 UI 化后基本不依赖 ps1） |
| cloudflared stderr 输出 URL 后仍需数秒才可达 | URL 解析到后先 HTTP 探活再报 ready，避免用户扫死链 |
| 端口冲突 | 本地代理端口从 31001 起探测，占用则 +1 |

## 5. 技术栈与工程结构

### 5.1 选型

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | Electron 33+ + TypeScript | 代理层可 100% 复用 Node 生态与既有代码 |
| 渲染层 | Vue 3 + Vite + Element Plus | 中文 UI 生态好、上手快（备选 React，无强依赖） |
| 进程间 | contextBridge 类型化 API + electron-trpc（评估） | 禁 nodeIntegration，安全默认 |
| 代理 | utilityProcess + 零依赖 node:http/net | 崩溃隔离、无供应链负担 |
| 存储 | JSON 原子写（自研 ~50 行） | 配置量小，不引数据库 |
| 打包 | electron-builder（NSIS） | Windows 主流；注意内置 cloudflared 后体积 |
| 测试 | Vitest（单测 proxy/tunnel-parser）+ Playwright（E2E 起 demo 服务→发布→curl 验证） | 隧道链路可全自动验证（本会话已验证过该测法可行） |

│  │  ├─ ipc.ts             # IPC 路由

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| Cloudflare Quick Tunnel 政策变化/限流 | 高 | 命名隧道为主推长期方案；架构上隧道层抽象接口，可换 frp 等备选后端 |
| 国内下载 cloudflared 失败 | 高 | 内置二进制 + 手动放置一等入口 + 多镜像 |
| 用户把无鉴权服务裸 exposed 后被扫 | 高 | PIN 默认不可关 + 限速 + 明示文案 + 日志 |
| dsh-pocket 为 GPL-2.0 | 中 | **只借鉴架构思路，不复制代码**；若确需复制片段，本项目须 GPL-2.0 开源 |
| Electron 安装包体积（含 52MB cloudflared） | 中 | 首启动下载模式作为备选发行版（portable-lite） |
| cloudflared 进程残留/僵尸 | 中 | 统一进程树 kill（taskkill /T 语义）+ 启动时清理孤儿 |

## 8. 测试策略

- **单测**：PIN 校验/限速/cookie 逻辑、cloudflared 日志解析（URL 提取）、registry 原子写；
- **集成**：本地起 http + ws demo 服务 → 走完整链路 → 用脚本模拟手机（登录→Cookie→WS 握手 101）
  —— 本会话已验证此测法可完全自动化；
- **混沌**：杀 cloudflared、杀代理进程、断网重连、端口占用、双实例启动；
- **安全**：错误 PIN 限速生效验证、未认证 WS 被 401、Cookie 篡改被拒。

## 9. 决策记录（2026-09-17 已定）

| 决策 | 结论 |
|---|---|
| 产品名 | **TunnelDock**（中文显示名：隧道坞） |
| renderer 框架 | **Vue 3** + Element Plus |
| cloudflared 来源 | **开发期直接用本机现成二进制**（`C:\Users\Administrator\.cloudflared\cloudflared.exe`，2026.8.2）；安装包是否内置留到 M4 打磨时再定 |
| 开源与否 | **闭源**。因此对 dsh-pocket（GPL-2.0）只借鉴架构思想，不复制任何代码；代理层以本会话自研的 auth-proxy.js 为蓝本（自有代码，无许可问题） |
| 平台 | 只支持 Windows 10/11 |
